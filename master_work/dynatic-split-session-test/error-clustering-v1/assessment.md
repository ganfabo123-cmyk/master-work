## 抽查实例

### 原生码：LNK1105

- 分组：`native-code-f3df951dc57a`，9 个切片、5 个 Session。
- 实际工具输出有 `LINK : fatal error LNK1105: cannot close file ...; error code 1224`。
- 正常汇集了不同文件和项目中的同码链接失败。对应消息模板进一步形成 8 个切片、5 个 Session 的组。
- 错误对象与消息明确，适合进一步阅读修复过程。此实验尚未证明全部成员采用同一修复，也未检查修复成功。

### 原生码：TS1484

- 分组：`native-code-0843503c3e0b`，1 个切片、1 个 Session。
- 实际 TypeScript 检查输出中，CSSProperties、ReactNode 等不同类型都报告同一个代码，文本明确提到 `verbatimModuleSyntax` 与 type-only import。
- 同码分组消除了对象名不同造成的碎片化；当前样本只有一个 Session，不代表这个错误只能由单 Session 提取。

### 异常类型：ModuleNotFoundError

- 分组：`exception-type-26f591172a0f`，4 个切片、4 个 Session。
- 工具输出分别包含缺少 pygame、pypdf、torch、fdroidserver 等模块的错误。
- 信息确实相关，但同名异常并不证明应该统一安装包；仍需查看调用的解释器、环境与实际修复。
- 对应消息模板 `ModuleNotFoundError: No module named <arg>` 也得到 4 个切片、4 个 Session 的组。

### 异常类型：UnicodeEncodeError

- 分组：`exception-type-e34a737b03fe`，2 个切片、2 个 Session。
- 两条实际工具输出均出现 `charmap` 无法编码某个字符，一条来自运行程序，一条来自读取 UTF-8 文本后的输出。
- 相比整个领域或一般工具序列，这个组提供了更具体的共同失败表现；后续可检查各自的输出编码修复和验证。

### 异常类型：TypeError

- 分组：`exception-type-c9afbe50532d`，4 个切片、4 个 Session。
- 有默认参数顺序、构造函数参数数量、运行时不支持 eval 等不同报错。
- 类型分组过粗，不能把整组直接归纳为一个修复 Skill；保留消息与上下文能让后续区分条件。

### 状态码：0xC00000FD

- 分组：`native-code-847c28ada68a`，2 个切片、2 个 Session。
- 本组目前只有助手文本报告，没有检测到对应状态码的工具输出。
- 两段原文都包含十进制 `-1073741571`，其中一段却将它解释为不同的十六进制码。脚本按数值统一为 `0xC00000FD`，保留原文，不采信助手的根因解释。
- 这说明必须区分实际输出与文本报告；同码组不能直接承担真实性验证。

## 三种策略的边界

- 原生码最清楚，但当前数据覆盖较少；通用退出状态也可能只是底层错误的包装。
- 异常类型增加覆盖，TypeError、RemoteException 等类型可能过粗；不自动推断语言或业务领域。
- 消息模板可识别没有编号的错误，但容易碎片化。路径、位置和引号中的变量会被标准化，完整原文仍由来源引用保留。
- 排除源码行、通过的负例测试、源码/搜索返回内容后，误报显著减少。这是诊断结构过滤，没有根据某个项目预设 Skill 词典。
- 原始文件中 59 个工具结果没有可读取正文，切片回填后同样如此；不推测这些空记录是否失败。
- 已检测到的工具错误证据，在 Session 与切片两个输入中完全一致。原始 Session 更多的部分主要是文本报告。这个结果只验证检测证据对应关系，不是所有真实错误的召回率。
