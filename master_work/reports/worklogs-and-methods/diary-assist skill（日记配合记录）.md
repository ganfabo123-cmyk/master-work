# Diary Assist

配合用户把当天值得记录的事情整理成日记条目并写入 Markdown 日记文件。

## 日记文件

- 首次使用：先确认日记文件路径与文件名（用户可能已有约定，如 `~/diary.md` 或项目内 `daily-diary.md`）。没有约定就问用户，不要自作主张选路径。
- 已有文件：追加写入，不重建、不覆盖历史内容。
- 若文件不存在且用户同意：创建文件后再追加。

## 条目格式（硬约束）

每篇日记以日期为间隔（每个日期一个分篇）。单个条目的固定结构如下，顺序不得调换、五列不得省略：

```markdown
## <YYYY-MM-DD 周X>

***<简短标题>**
我在<X>时<X>分做了<事情>（描述完整过程：触发 → 动作 → 结果，写全过程，不要一句话概括）

已完成：<本次做完的事，可多条>
学到了什么：<关键收获 / 方法 / 数据，可多条>
未完成：<遗留事项；没有则写"暂无">
今天修正了什么认知：<今天推翻或纠正了哪些旧看法 / 结论；没有则写"暂无">
现在状态：<当前进展 / 下一步>
```

- 语言：中文（用户语言）。
- 标题：简短、能概括该条内容（如"毕设聚类实验重跑"、"AirLLM 学习"）。
- 时间：写入时取当前实际时间，格式为"X时X分"。
- 多条事项可分多个条目（各带标题）追加到同一天分篇下。

## 记录流程

1. 取当前时间。
2. 判断记录对象：用户明确要求记录的；或对话中出现值得沉淀的事项（学习结论、实验数据、决策、认知修正、归档链接）且用户示意记录。用户说"不用记"时不记录。
3. 按条目格式组织内容。
4. 追加到日记文件：当天已有分篇 → 在该分篇内追加；新的一天 → 新建日期分篇标题再写入。
5. 完成后向用户确认，给一句话摘要即可，不重复粘贴全文。

## 典型记录内容来源

- 学习心得：GitHub Trending / 技术项目 / 工具的原理、关键数据、实测结论
- 论文阅读：题目、arXiv ID、核心方法、对自己研究的启发
- 实验进展：设计、结果数据、成本统计、与预期的对比
- 排障过程：现象 → 排查 → 根因 → 修复
- 决策：投稿目标、实验分组、技术选型等与导师 / 协作方确认的结论
- 归档索引：新建文档 / 链接时记一行索引

## 边界

- 不修改历史分篇；确需修正历史条目时先问用户。
- 不把推测写进"已完成"，推测只能放在"未完成"或"现在状态"。
- 涉及隐私或敏感信息（个人私密、密钥、内部代码）默认不写入，除非用户明确要求。
- 数字、链接、arXiv ID 等必须来自对话或已验证来源，不编造。
