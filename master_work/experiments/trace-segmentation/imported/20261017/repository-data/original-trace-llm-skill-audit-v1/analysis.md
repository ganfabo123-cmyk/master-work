## 提取出的 Skill

### S01 把多阶段需求转成明确的本轮范围与排除项

收到包含多个 milestone 的需求时，先写清本轮要完成、明确跳过和未来分支，再按范围实现；用户改变阶段时重新读取当前状态，只扩展到新授权阶段。

来源：`07b57159-218e-4330-a64e-0ec4b4355056`（event 19：目标到 milestone 3；event 192：做 milestone 4、跳过 5、做 6）；`4222016d-1932-4abb-94b3-463203bd8876`（event 270、621、688 的阶段继续与扩展）。

适用边界：有路线图或阶段表，且阶段排除项可以从用户或文档确定。高质量原因：它把阶段约束变成可验收的范围控制，避免把未来能力混进当前实现。

### S02 在训练数据切分前保留对话角色和来源元数据

不要把混合 `corpus.txt` 当成唯一数据源；先检查生成脚本的真实输入，再以保留 `user/gpt` 等角色的 JSONL 为主，并显式编码纯文本来源。

来源：`ba1b4916-b581-4e05-9a5c-c1d8ffc9b50a`（event 37：不要丢失 `user/gpt` 元数据；event 195：`corpus.txt` 实际未被 trainer 使用）。

适用边界：多来源、混合格式训练/评估管线。高质量原因：它针对数据血缘与语义保真，能发现“文件存在但管线没有使用”的具体错误；单一来源也足以证明该 Skill。

### S03 按硬件能力选择精度并用梯度累积保留上下文长度

先按 GPU 架构排除不支持的精度；显存不够时优先把 micro-batch 降到 1、用 gradient accumulation 保持有效 batch，保留硬约束 context size。

来源：`ba1b4916-b581-4e05-9a5c-c1d8ffc9b50a`（event 185：A500 不支持 FP8；event 190：`batch_size 1`、`grad_accum 32`、`1024 ctx`）。

适用边界：显存受限且上下文长度不可牺牲的训练任务。高质量原因：同时给出硬件事实、参数优先级和具体配置，而非泛泛建议“减小 batch”。

### S04 用阶段专属测试套件证明阶段完成后再更新文档

阶段完成的顺序是：阶段测试、既有回归、环境噪声隔离、再更新 README/计划表；锁文件或旧进程造成的失败先单独处理，不能直接算作代码失败或成功。

来源：`39082932-131c-40a9-872d-1d3ac8ed1fd6`（event 1433：`48/48 + 17/17` 后才更新 README）；`6a7964ed-6f92-4eee-ae5e-3f91a6445833`（event 581：三个阶段套件全通过且库构建干净）；`4222016d-1932-4abb-94b3-463203bd8876`（event 621：构建无错误后标记 M2/M3 完成）。

适用边界：有独立阶段测试入口的编译器、运行时、游戏或应用工程。高质量原因：规则跨三个不同工程，绑定了测试证据、环境诊断和交付记录。

### S05 用语法审计和多版本矩阵实现兼容性

先找出明确的版本阻塞点并替换兼容写法，再在所有可用解释器版本上跑同一回归套件；当前版本通过不等于多版本兼容。

来源：`07b57159-218e-4330-a64e-0ec4b4355056`（event 425 要求支持 3.7；event 430 找到 `kw_only=True` 与 union 语法阻塞；event 482 报告 3.7、3.12、3.14 一致通过）。

适用边界：需要支持多个语言/运行时版本，且能列出实际版本。高质量原因：轨迹覆盖需求、阻塞点、实现和矩阵验证的完整闭环。

### S06 把可嵌入库与 CLI 分离并提供窄的纯 C ABI

核心 lexer/parser/codegen 和批处理逻辑放库中，CLI 只负责参数、文件和输出；跨 C/C++ 边界只暴露纯 C 结构和错误结果，避免 STL、异常和 C++ 类穿过 ABI。

来源：`92833a43-c30d-4b44-8447-c32ee17d6e6e`（event 2：CLI 成为库的使用者；event 193：宿主只需要公开 C API）。

适用边界：编译器、解释器或数据工具需要被其他语言嵌入。高质量原因：明确规定职责、ABI 和异常/内存边界，能直接指导架构切分。

### S07 让头文件、实现文件和构建目标的边界可检查

固定 `include` 只放头文件、`src` 只放实现文件，让 Make/脚本目标反映目录约定；构建失败时检查真实编译命令、脚本语法和测试入口，而不只修 IDE 报红。

来源：`39082932-131c-40a9-872d-1d3ac8ed1fd6`（event 27：保持当前根目录；event 39：include/src 分界；event 407：Make 测试命令实际失败）。

适用边界：有公开头文件和多平台构建脚本的 C/C++ 项目。高质量原因：把目录、构建和测试入口统一为可审计边界。

### S08 用对象大小和拷贝路径定位启动期栈溢出

测试程序启动即崩溃时，先看大型结构体是否按值声明或被隐式复制；改为引用/指针后先跑最小测试，再跑全套测试验证因果。

来源：`479c5e9f-a299-457f-8459-5948adf8aa8e`（event 324：1 MB `AtomTable` 被复制到栈；event 334：17 个 atom 测试通过）；`c99032e9-377b-4ae9-a9a9-ec7752b059cd`（event 1203：同样确认按值复制导致崩溃）。

适用边界：C/C++ 启动崩溃、有限栈空间或大型状态对象。高质量原因：同一具体诊断规则在两个工程得到独立证据。

### S09 用路由事实和请求生命周期排查前端 404

先核对实际目录参数名与 server loader 的环境变量生命周期；配置只在请求期可见时，用同源 proxy 转发 `/db/*`，页面 loader 改用相对路径，再以真实 HTTP 状态验证。

来源：`c84c0ad3-c368-40df-87b1-5ef9effe237a`（event 464：环境变量未加载；event 493：增加 `+server.ts` proxy；event 504：实际是 `[slug]` 而不是 `[name]`）。

适用边界：文件路由、SSR loader 和后端 API 代理组合。高质量原因：把 404 分成可证伪的参数事实和运行时作用域两层。

### S10 用户指出本地字体后先检查资产和编译路径

先读字体目录和现有 SCSS token，用 `@font-face` 和正确相对产物路径接入；本地资产存在时不应无谓引入远程字体，并要检查编译后 CSS 的实际加载路径。

来源：`09d9abe9-0a02-4bd1-8129-3b864695079d`（event 51：字体已经在 fonts 目录；event 57：改用本地 `@font-face`）；`7563bddf-c1a0-4c3e-86ee-062bf288e6d3`（event 13：设计系统约束需先读现有项目）。

适用边界：前端字体迁移和设计系统接入。高质量原因：把资源事实、CSS 接入和产物检查连成可复用流程。

### S11 用新数组引用触发 Alpine 等响应式系统更新

数据源已经变化但 UI 不动时，检查响应式系统是否按引用比较；刷新时赋值一个新数组对象（如 spread copy），再验证界面更新。

来源：`09d9abe9-0a02-4bd1-8129-3b864695079d`（event 557：live array 的同一引用不会触发 Alpine；event 565：spread 生成新引用）。

适用边界：Alpine、React store 或其他按引用检测变化的 UI。高质量原因：从现象定位到机制和最小修复，具体且可复现。

### S12 让窗口打开和进程清理具备幂等生命周期

重复打开已存在窗口时不得重复 `createProcess`；关闭窗口必须通过 `onClose` 调用 `terminateProcess`；验证重复点击、关闭和进程表都没有泄漏。

来源：`09d9abe9-0a02-4bd1-8129-3b864695079d`（event 577：重复 open 泄漏进程；event 596：`isOpen` guard 与 `onClose` cleanup）。

适用边界：桌面式 Web UI、窗口管理器和有 open/close 副作用的系统。高质量原因：同时覆盖幂等入口、资源创建和释放。

### S13 用同源代理消除前端运行时后端地址分歧

把前端请求收敛到同源 server proxy，页面只依赖相对 URL；proxy 负责后端地址和环境差异，同时继续核对路由参数的实际名称。

来源：`c84c0ad3-c368-40df-87b1-5ef9effe237a`（event 493：proxy 让 loader 使用相对 URL；event 504：修正 `params.slug`）。

适用边界：环境变量作用域跨开发、SSR、部署而不一致的前后端项目。高质量原因：通过稳定边界减少环境变量分歧，而非反复硬编码后端地址。

### S14 把多分辨率界面布局变成运行时几何

定义允许的分辨率选项和运行时 `ScreenConfig`，用 active width/height 派生网格、侧栏和 cell size；渲染纹理可以保留最大容量，但按当前 viewport 合成，并用明确比例验证布局。

来源：`4222016d-1932-4abb-94b3-463203bd8876`（event 887：三种分辨率选择；event 1166：网格 80%、侧栏 20%）；`d4c4d47d-642c-4c26-a866-51ab85587896`（event 49：溢出修复；event 414：窄屏分页而非继续挤压）。

适用边界：游戏 HUD、仪表盘和响应式界面。高质量原因：把溢出、分辨率和缩放统一成运行时几何模型。

### S15 迁移低级启动/显示路径时以运行时事实校验协议兼容性

跨 MB1/MB2、UEFI/GOP 等协议迁移时保留显式入口，先核对 boot tag 和 framebuffer mode，再依真实地址映射修复构建模块、显示抽象和镜像，最后重新启动验证。

来源：`17c2cf98-e64a-43c6-932e-fa7efcade358`（event 259：MB2 黑屏；event 279：实际打印 `[BOOT] MB2 boot`；event 310：同时支持 MB2/MB1）。

适用边界：操作系统、引导、驱动和硬件协议迁移。高质量原因：要求以运行时事实而不是旧协议假设驱动修复。

### S16 用已知工作实现对照并缩小退出崩溃的最小路径

固定地址退出崩溃时，对比同系统中能正常退出的程序，逐步移除非必要清屏、光标恢复或忙轮询，建立最小安全路径；未证实根因要保持为假设。

来源：`f93127ef-dec9-4d58-964b-ee660964ec4d`（event 168：htop 退出 GPF；event 187：对照 quill；event 213：改用已知安全的 `getChar()` 模式）。

适用边界：内核态、嵌入式和终端交互程序。高质量原因：结合对照、缩小和证据分级，避免在根因不明时过度断言。

### S17 从参考源解析资源并用结构性计数验证

完整读取结构化参考源，写解析器把资源转换成运行时数据，不手抄；接入前验证帧数、宽高和关键映射与来源一致。

来源：`07b57159-218e-4330-a64e-0ec4b4355056`（event 338：解析完整 `animation.c`；event 371：验证 12 帧、64×64）。

适用边界：参考代码、协议样例和资源表迁移。高质量原因：把忠实迁移和结构性验证结合，能捕获丢帧和尺寸错误。

### S18 对高影响操作实施分层开关、精确确认和公开警告

破坏性、资源密集或外部副作用功能必须先过显式 flag，再在 CLI 展示影响并要求精确确认；任何非确认输入都 no-op，且 abort path 要测试。

来源：`07b57159-218e-4330-a64e-0ec4b4355056`（event 658：先警告再确认；event 675：只有精确 `YES` 才继续）。

适用边界：高成本或不可逆操作。高质量原因：证据完整覆盖默认阻断、影响披露、精确确认和取消验证；保留的是安全协议，不是具体危险功能。

### S19 把不同部署/政策要求隔离为独立实现

同一能力在不同平台或政策目标上有实质差异时，维护独立实现文件和明确选择点，共享入口只选择，不把目标规则揉成模糊分支。

来源：`07b57159-218e-4330-a64e-0ec4b4355056`（event 19：要求 GitHub/Codeberg 分离；event 582：报告两个独立实现文件）。

适用边界：开源/企业、测试/生产或平台合规差异。高质量原因：把政策差异变成可审计的模块边界。

### S20 敏感配置采用加密存储、分离盐和可验证初始化

敏感地址或配置不直接写进仓库；用随机/运行时输入加密存储，分离盐和代码路径，提供 setup/show/clear 入口、非交互初始化参数和加密-解密 round-trip 测试。

来源：`07b57159-218e-4330-a64e-0ec4b4355056`（event 585：加密值并分离盐；event 632：为自动化增加 `--address`；event 642：round-trip 通过）。

适用边界：钱包地址、API token、部署密钥等敏感配置。高质量原因：同时覆盖存储、输入、自动化和验证，不把具体项目地址当作 Skill。

### S21 清理工程时只删除可证明的派生物并同步构建入口

删除前列出目标来源和引用关系，只删旧输出、重复源码和测试产物；删除后检查树、构建脚本和资源路径，并更新 README/.gitignore。

来源：`4222016d-1932-4abb-94b3-463203bd8876`（event 1174：列出 stale output/duplicate；event 1190：确认剩余树）；`92833a43-c30d-4b44-8447-c32ee17d6e6e`（event 195、229：更新忽略规则并确认零构建产物被 stage）。

适用边界：含缓存、复制源码和编译产物的仓库。高质量原因：把破坏性清理限制为有引用证据的目标，并要求清理后重新检查。

### S22 构建后恢复派生文件并保持 PR 只含意图变更

构建可以生成临时派生文件，但提交前逐项核对 diff，恢复未要求的生成物，只 stage 直接相关源文件，并确认 PR 与真实最小变更一致。

来源：`2965219c-42ad-45af-889c-4581ecbe0103`（event 235：恢复派生文件、只 stage `models.json`；event 252：最终只有 31 行目标变更）。

适用边界：生成代码、索引、锁文件或构建产物会改变工作区的 PR 流程。高质量原因：直接保护审查可读性和变更归因。

### S23 外发轨迹前做公开性核验、脱敏复查和信任边界停机

外发前核对公开性和许可证，定位单个会话，本地自动脱敏，再人工检查姓名、路径、内部 URL 和部署信息；必须有用户确认，遇到 trust-boundary 拒绝就停止，不能绕过。

来源：`2965219c-42ad-45af-889c-4581ecbe0103`（event 266：公开性和显式确认）；`89cf9e13-a4bd-4cf9-9486-7c89737bec1b`（event 225：轨迹包含个人和运行信息）；`3be5ba0c-62b2-4645-8589-9216be0c10d8`（event 1267：安全分类器阻断上传且不绕过）。

适用边界：日志、会话、代码或数据集上传到第三方/公共服务。高质量原因：形成公开性、最小范围、脱敏、人工复查、确认和停机的完整安全顺序。

### S24 从配置和迁移代码追溯字段语义再解释数据

字段含义不能按列名猜；先查正负选项定义，再查迁移/写入代码如何绑定回答两侧和用户偏好，最后给出字段级解释。

来源：`comparia-voting-fields-anon`（event 29：`useful`/`superficial` 的配置来源及 `migrate_votes.py:48-60` 绑定）。

适用边界：历史数据、匿名标注、问卷字段和迁移 schema。高质量原因：要求定义点与写入点共同证明语义，避免方向和模型侧解释错误。

### S25 状态型解释器先建立状态再按要求的顺序执行

当语义要求值正向求值而语句反向执行时，分为两个阶段：正向预计算并建立赋值状态，再反向执行副作用；对反向先读取赋值的语句写回归测试。

来源：`07b57159-218e-4330-a64e-0ec4b4355056`（event 101：值正向、执行反向；event 175：预计算还必须存储赋值后再反向重放；event 186：全部通过）。

适用边界：解释器、规则引擎、构建计划和其他纯求值/副作用顺序分离的系统。高质量原因：它从具体失败推导出两阶段执行模型，远比“加测试”具体。

## rejected_or_weak

以下候选保留在审计中但没有混入高质量清单：

1. `Read/Edit/Compile/Test` 的一般顺序：所有开发轨迹都可能出现，缺少具体不变量。
