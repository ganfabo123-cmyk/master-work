## 1. 研究目标与语义主线

### 1.1 研究问题

Coding agent 在真实开发任务中会出现"卡住/空转"行为：同一错误反复出现、同一命令重复执行而无产出、被表象误导走向错误修复方向。本研究探索一种**运行时触发式动态检索层**：将历史经验沉淀为标准化 skill 语料，当运行轨迹出现特定信号时检索相关 skill，将其作为可选 hint 提供给模型，由模型自行决定是否采纳。

### 1.2 语义主线

在状态型 Agent 循环 `State → Observation → Policy → Action → Environment → New State` 中，动态检索层插入在 Observation 阶段：

```text
Runtime（流式产出 raw trace）
    → 检索程序接收事件，累计成统一轨迹
    → 判断是否触发检索（trigger）
    → 从轨迹构造查询（query = 最新 user input 原文）
    → 与记忆语料做相似度匹配（embedding cosine）
    → 返回统一结构的检索结果（不写入 prompt）
Runtime 决定是否把结果作为 hint 注入模型上下文
```

职责边界：检索程序**只返回结果**，不修改轨迹、不写 Prompt、不维护会话状态；注入决策权在 Runtime。

### 2.3 审计方法

三层方法（脚本见 §6.2，已入库 `audit_tools\`）：

1. **全量统计**（`audit_traces.py`）：每 session 的事件数、工具调用分布、错误结果数、时间跨度，用于排除无内容 session 和确定审计顺序；

- **A（真实卡住）**：出现空转循环、误导性方向、或用户重复报告，且≥2 处可定位证据；
- **B（合法迭代）**：失败-修复-前进的正常开发循环；
- **C（证据不足）**：内容过短无法判断。

- 每个经验沉淀为独立目录 `<skill-name>\SKILL.md`，标准 frontmatter（`name` + `description`）+ Markdown 正文；

## 4. 检索程序架构（retrieval_program.py，1330 行）

### 4.1 固定框架与开发者槽位

文件分两层：固定框架（不可改）+ 开发者实现区（7 个槽位，本日改动全部在此区内）。

| 槽位函数 | 职责 | 当前实现（策略 v1） |
| --- | --- | --- |
| `developer_material_sources()` | 声明语料文件清单 | 仅 `skills_tests\**\SKILL.md`（10 个） |
| `register_developer_parsers()` | 注册 .md 解析器 | SKILL.md → 提取 frontmatter description |
| `developer_embedding_api_config()` | embedding API 配置 | 从 `.env` 读全部配置，脚本内无默认值 |
| `developer_trace_converter()` | raw trace → 统一事件 | user role/type 归一为 `user_input` |
| `developer_should_retrieve()` | 触发判断，返回 bool | 最新事件为 `user_input` 即触发 |
| `developer_build_query()` | 轨迹 → 查询 | 查询 = 最新 user input 原文；top_k 默认 3 |
| `developer_retrieve()` | 查询 × 语料 → 命中 | `SkillDescriptionSimilarityStrategy`（§4.3） |

固定入口 `dynamic_retrieval_test.py` 只做一件事：`PROGRAM = create_developer_program()`，外部调用 `PROGRAM.handle_raw_trace(raw_trace)` 逐事件喂入。

### 4.2 结果协议（状态机）

每次 `handle_raw_trace` 返回一个 `RetrievalResult`，状态四枚举：

| 状态 | 含义 |
| --- | --- |
| `NOT_TRIGGERED` | 触发策略决定不检索（非 user_input 事件） |
| `EMPTY_QUERY` | 触发了但查询文本为空 |
| `NO_MATERIALS` | 无可检索语料 |
| `COMPLETED` | 检索完成（items 可为空列表，空 ≠ 异常） |

命中结构 `RetrievalHit`：`document`（含 `document_id`、`retrieval_content`=description、`full_content`=全文）、`score`（余弦相似度）、`rank`、`matched_content`、`metadata`。策略抛异常会原样上抛，与"空结果"严格区分。

### 4.3 策略 v1：SkillDescriptionSimilarityStrategy

```text
触发：最新事件是 user_input
查询：user input 原文（不拼接历史）
匹配：query 向量 × 每个 skill description 向量 的余弦相似度
过滤：score < min_similarity(默认 0.25) 丢弃
排序：相似度降序，截取 top_k（默认 3）
返回：matched_content = 完整 skill 正文（full_content 去掉 YAML frontmatter）
缓存：description 向量按 (document_id, description) 缓存，10 条语料只嵌入一次
降级：embedding API 未配置时返回空命中（不抛异常）
```

设计取舍：检索面用 description（短文本、信号密度高），注入面返回正文（完整可执行经验），两者分离。
