## 1. 设计目标与约束

### 1.1 问题

策略 v1（全局暴力余弦）在语料规模 N 增长时本地计算线性膨胀；而纯精确签名匹配又受"预设覆盖"限制。目标：设计一个**随语料从 10 增长到 10⁶ 都不需要推倒重建**的检索结构，且精确度与复杂度可同时受控。

### 1.2 硬约束

| 约束 | 内容 |
| --- | --- |
| 实现 | 纯 Python 标准库优先（当前零第三方依赖） |
| 延迟主导项 | embedding API 为远程调用，每次 ~100ms RTT，**与 N 无关** |
| 规模演进 | skill 只增不减（10 → 10⁴ → 10⁶），量级不回落 |
| 职责边界 | 检索程序只返回结果；注入决策在 Runtime |

### 1.3 核心设计决策（一览）

| 决策 | 结论 |
| --- | --- |
| 索引主通道 | 结构化触发签名 + Aho-Corasick 自动机（精确、O(\|q\|)、与 N 无关） |
| 语义通道 | 保留 embedding，作为签名未覆盖的兜底 |
| 规模扩展 | 两级质心路由（聚类节点 × 节点内线性暴力），B=1 时精确退化为现状 |
| 质量闭环 | 几何反馈（影子日志）× 效用反馈（消费方隐式评分）双通道 |
| 存储结构 | 平铺文件堆，索引全部为可重建派生物 |

## 2. 复杂度基线与实测（现状策略 v1）

### 2.1 调用链分阶段复杂度

设 N=语料文档数，D=embedding 维度（text-embedding-v4 约 10³），T=user input 长度，E=session 事件数，U=其中 user_input 数。

| 阶段 | 触发条件 | 复杂度 | 说明 |
| --- | --- | --- | --- |
| 事件转换 | 每事件 | O(事件长度) | role/type 归一化 |
| 触发判断 | 每事件 | O(1) | 只看 latest_event，不扫历史 |
| 查询构造 | 仅 user_input | O(T) | 取最新事件原文 |
| 语料向量缓存 | 冷启动一次 | O(N) 次 embed | 10 条按 batch 合并为 1 次 HTTP |
| 查询嵌入 | 仅 user_input | **1 次 RTT** | 每次检索的真实延迟大头 |
| 余弦相似度 | 仅 user_input | **O(N·D)** | 本地计算主导项 |
| 排序+截断 | 仅 user_input | O(H log H) | 可用堆降为 O(N log k) |

整体：session 内本地 O(E + U·N·D)；网络 = 1（冷启动）+ U（每查询 1 次）；空间 O(N·D) 向量缓存 + O(E) 轨迹。

### 2.2 实测：实现常数决定"免费区间"

**关键教训：乘加次数 ≠ 耗时，中间差一个实现常数。** 本地耗时 ≈ N×D×c：

| 实现 | 实测常数 c | 依据 |
| --- | --- | --- |
| 纯 Python（当前 `_cosine_similarity`） | ≈120 ns/乘加 | 单条 D=1024 余弦 122 µs |
| numpy 向量化 | ≈0.08 ns/乘加 | 10⁴×1024 矩阵向量积 0.8 ms |

相差 **~1500 倍**（解释器开销：字节码分发 + 浮点装箱；硬件本身做 10⁷ 次浮点运算只要微秒级）。带入网络 RTT ≈100ms 基准：

| N | N×D | 纯 Python（当前） | numpy |
| --- | --- | --- | --- |
| 10 | 10⁴ | 1.2 ms（占比 ~1%，可忽略） | ~0.001 ms |
| 10³ | 10⁶ | 122 ms——已追平网络 | ~0.1 ms |
| 10⁴ | 10⁷ | 1.2 s——不可接受 | 0.8 ms，仍可忽略 |

**结论**：当前 N=10 瓶颈是网络而非算法；纯 Python 实现的免费区间只到 N~10²–10³；"N≤10⁴ 免费"只在向量化实现下成立。扩展第一优先级是 numpy 化（常数降 1500 倍），而非 ANN 索引。

### 2.3 论文可用的公式化表述

本地检索耗时 = N·D·c_impl，其中 c_impl 由实现决定（解释型 ~10²ns/op，向量化 ~10⁻¹ns/op）；系统延迟 = max(网络 RTT, N·D·c_impl)。免费条件：N·D·c_impl ≪ RTT。

## 3. 对数级索引结构选型（及最终判决）

### 3.1 问题拆解

整体检索 = 查询嵌入（O(1)，与 N 无关）+ 匹配（线性所在）+ top-k 选取。**D≈10³ 高维空间中精确树（KD/Ball）因维度灾难失效**，"精确 + 对数"不存在，必须靠近似结构或符号结构。

### 3.2 候选对比

| 结构 | 随 N 的查询复杂度 | 精确性 | 增量插入 | 对 skill 结构的利用 | 维护成本 |
| --- | --- | --- | --- | --- | --- |
| 暴力点积（现状） | O(N·D) | 精确 | O(1) | 无 | 零 |
| HNSW | O(polylog N) | 近似（召回 95~99%） | ✓ | 无（黑盒） | 库现成 |
| 语义概念树 | O(b·D·log_b N) | 路由错一级=整棵子树丢失 | ✓ | 强（索引=分类法） | 人工建树 |
| **签名自动机** | **O(\|q\|)，与 N 无关** | **精确** | ✓ | **强（frontmatter triggers）** | 半自动抽取 |
| 倒排+WAND | 平均次线性 | 精确 | ✓ | 弱 | 分词/权重 |

### 3.3 判决：签名层在双轴上同时最优

- **精确度**：精确匹配消除向量检索三噪声——近似召回损失、阈值调参、易混淆家族（LNK1105 vs LNK1107 的 description 高度相似，向量分数咬近，字面匹配零混淆）；且命中可审计（能指出输入中哪个串触发）；
- **复杂度**：O(|q|) 与 N 无关（比对数更低一档）；**命中时连查询嵌入都省掉**，整体延迟从"1 RTT + 匹配"降到纯本地微秒级——HNSW 做不到这点；
- **代价（覆盖面）可被前提消解**：用户前提"可自由调整 skill 存储结构" → 把覆盖问题从"索引缺陷"转化为"语料编写规范"（每个 skill 必须声明 triggers；声明不出的标注语义兜底）；
- **失败模式良性**：签名 miss → 落语义兜底（退化为现状），不产生错误 hint；向量阈值预设错 → 方向性误导。签名层的预设成本是数据挖掘问题（可半自动），不是穷举问题。

各候选的牺牲：暴力花 O(N) 买精确；HNSW 花精度买复杂度；概念树花错误级联+人工维护买可解释性；**签名层把权衡本身消掉，代价转嫁给语料规范**。

### 3.4 推论：完美签名下存储与索引解耦

若每个 skill 具备满分签名（完全性/区分性/**在场性**三条件），则：存储层=平铺文件堆（线性）；索引层=启动时派生的自动机（O(签名总长)，可重建）；查询层=O(|q|)。**三层全是线性或常数，对数结构在体系内失业。** 这是数据库"堆文件+派生索引"模式的直接应用；成本转移为语料规范经营（"语料规范即索引"）。

## 4. 签名层设计

### 4.1 三层结构

```text
① 存储层：SKILL.md frontmatter 增加结构化 triggers 字段
② 索引层：启动时全部签名构建 Aho-Corasick 自动机（trie + 失配指针）
③ 查询层：对输入一次线性扫描 O(|q|) → 命中路由 / 未命中转语义兜底
```

### 4.2 存储格式规范

```yaml
---
name: windows-lnk1105-error1224-file-locked
description: Windows 下链接失败：LNK1105 cannot close file、error code 1224...
triggers:
  - "LNK1105"
  - "error code 1224"
  - "cannot close file"
---
```

签名选择标准：

| 标准 | 好签名 | 坏签名 |
| --- | --- | --- |
| 特异性 | `error code 1224`、完整报错句式 | `"404"`、`"not found"`（短泛串误报） |
| 稳定性 | 机器模板文本（错误码、固定文案） | 人类改写说法 |
| 多对一 | clang/MSVC 不同措辞挂同一 skill | 一签名多义 |

行为模式型 skill（如"用户重复报障"）声明空 triggers，标注 `fallback: semantic`。

### 4.3 索引与查询

- 构建：O(签名总长)， trie 共享公共前缀（LNK1105/LNK1107 共享 `LNK110`），失配指针 KMP 同款，保证扫描不回溯；大小写归一（casefold）后构建与扫描；
- 查询：O(|q| + 命中数)；命中时短路返回（跳过 embedding RTT）；多签名命中同一 skill 提升置信度；支持在线插入（或批量重建）。

### 4.4 演示验证（`signature_layer_demo.py`，真实运行输出）

5 类测试输入的行为：

```text
输入[a20a4070 的真实 tool_result 片段]:
  -> 签名命中 3 处，路由到 1 个 skill（跳过 embedding RTT）:
     windows-lnk1105-error1224-file-locked  <= 'lnk1105'@19, 'cannot close file'@28, 'error code 1224'@72

输入[易混淆家族：LNK1107 vs LNK1105]: 报 LNK1107 invalid or corrupt file:怎么办
  -> windows-lnk1107-corrupt-binary  <= 'lnk1107'@2, 'invalid or corrupt file'@10
     （零混淆：未沾染 LNK1105 skill）

输入[PowerShell 假故障（09d9abe9 原文）]:
  -> powershell-command-not-found-windows  <= 'is not recognized as a name of a cmdlet'@16

输入[改写型输入：不含任何原文签名]: 链接器说文件关不上，好像是权限问题
  -> 无签名命中 => 走语义兜底（embedding 层）

输入[无关输入]: 帮我写一个快速排序
  -> 无签名命中 => 走语义兜底
```

验证了三性质：精确路由（多签名汇聚）、家族区分（字面匹配零混淆）、诚实边界（改写/无关输入正确落空转兜底，签名层不猜）。

### 4.5 签名质量运营（回应"预设会有坑"）

| 担忧 | 缓解 |
| --- | --- |
| 签名要预设得很好，否则命中不了 | 原料是**机器生成的模板文本**（错误格式数十年稳定），非人类语言；"预设好"=挖掘头部模板（正则抽 `LNK\d{4}`、`error code \d+`、引号内原文），不是穷举说法 |
| 覆盖不足 | 反馈回路：未命中但语义命中的 (query, skill) 对 = 签名挖掘素材（对比性 n-gram，见 §7.4），人审入库；命中率随使用增长 |
| 失效后果 | miss = 良性降级到语义兜底，不产生错误 hint；下界即现有方案 |

失效模式清单：人类改写（→语义兜底）、拼写错误（不做模糊匹配，防误报）、同问题不同报错格式（多对一挂变体）、中英混杂（双语签名）、泛化串误报（特异性规范）。

## 5. 两级质心路由架构（规模扩展主干）

### 5.1 结构与复杂度

```text
路由层：B 个节点（语义类目），每节点一个质心向量
节点内：线性 skill 集合，numpy 暴力点积
查询：embed 一次 → 对 B 个质心点积 → 取节点束 → 节点内暴力 → 去重 top-k
复杂度：O(B·D + m·(N/B)·D)；B≈√N 时平衡，总代价 O(√N·D)
```

10⁶ 语料：B≈1000、每节点 1000 skill → ~2×10⁶ 次乘加，毫秒级。

**核心设计决策：单一系统覆盖全量级，无切换开关。** N=10 时 B=1（单节点装全部）精确退化为现状；N 增长时 B 沿 √N 演化，无需迁移。这消除了"量级超过 10⁴ 很难回落"的担忧——不存在切换点。

该结构即 IR 领域的 **cluster pruning / IVF 索引**（Faiss 核心思路）的语料应用；设计者独立推导得出，可作论文叙事。

### 5.2 路由规则：(τ, m) 双规则取并集

```text
选中节点 = {cos(q, 质心) ≥ τ} ∪ {点积 top-m}
```

- m（束宽）管召回下限：查询落在两簇交界时兜住两边；
- τ（绝对阈值）管质量下限：离所有簇都远的查询（垃圾/新领域）转全局兜底，不硬塞；
- **标定不靠拍脑袋**：影子日志对 (τ, m) 网格扫描，画"路由召回率 vs 平均每查询搜索节点数"**帕累托曲线**取拐点。"根据效果调整"的依据是日志指标而非体感。

### 5.3 图的形态

质心扁平路由为主；边只在"top-1 节点内分数低于阈值时沿相关类目边扩一圈二次检索"场景有用——稀疏边、按需建。**先要的是两层树 + 少量旁路边，不是大图。**

### 5.4 诚实边界：该架构解决什么、不解决什么

| 解决 | 不解决 |
| --- | --- |
| 本地计算随 N 的扩展性 | 每查询 embedding RTT（恒定 ~100ms，与 N 无关） |
| | 内存：10⁶ × 1024 维 × 4B ≈ **4GB** |
| | description 修改的重嵌入成本（O(改动量) 次 API） |

## 6. 聚类方法

### 6.1 聚类语料：`name + description`（空间一致性原则）

**选择标准只有一条：聚类空间必须与检索空间一致**——查询用"query × description"，聚类就必须聚在 description 向量上。

| 语料 | 用否 | 理由 |
| --- | --- | --- |
| name + description | ✓ 主语料 | 与查询匹配文本完全一致；短、信号密度高 |
| description + triggers 低权拼接 | 可选 | 把字面匹配词拉进语义空间 |
| full_content | ✗ | 正文噪声稀释信号；正文一改就重聚类，无谓抖动 |
| 影子日志历史 query | 第二阶段 | 查询质心校准（§7.3） |

硬约束：聚类与查询**同一 embedding 模型**（跨模型空间不可比）；换模型=全量重嵌+重聚类；向量归一化到单位球，用**球形 k-means**（点积当相似度，质心取均值后重归一化）。

### 6.2 k 的选择：两道关

**第 1 关（intrinsic，收窄范围）**：

- **Silhouette 系数**（cosine 版）：`(b−a)/max(a,b)`，取最大者；
- **稳定性**：bootstrap 重采样聚两次，算 **ARI（调整兰德指数）**，排除随机波动结构；
- 候选范围 [√N/4, 4√N]（√N 为路由/节点内成本平衡点）；用 bisecting k-means 保留层级树形。

**第 2 关（extrinsic，拍板）**：

- 伪真值 = 影子日志中 embedding 全局暴力检索的 top-1 skill；
- **路由命中率** = 查询被分到的节点束包含真值 skill 所在节点的比例；
- 在第 1 关收窄的 k 区间内，选"路由命中率达标前提下 B 最小"的 k。

几何指标选几何紧凑簇，任务指标选有用的簇——两层缺一不可。

### 6.3 软分配与不变量

- **软分配**：skill 可属"质心距离 ≤ τ_assign 的前 ≤2 个节点"——边界 skill（描述横跨两类）硬塞必错；多列表收录是 IVF 标准做法，检索时按 skill ID 去重；
- **不变量（时刻成立）**：节点质心 = 当前成员向量均值。增：和+=新向量；删：和−=旧向量；改：减旧加新——全 O(1) 增量。重聚类**触发式**（节点规模 > 2×目标、或路由召回率下滑超阈值）才局部执行。**聚类可以次优，不变量不能破**——破了路由全错。

## 7. 双反馈闭环（几何 × 效用）

### 7.1 两条独立反馈

```text
几何反馈（影子日志）：query→skill top-1 伪真值 → 路由命中率 → 标定 k/τ/m   【聚得对不对】
效用反馈（消费方）：  好差评 → per-skill 召回率/可用率 → 节点归属 + 内容修订  【聚了有没有用】
```

两路独立采集、汇到同一动作接口（节点成员变更），互相校验：几何说该聚一起而效用说没用 → 通常是 description 写偏；双好的簇 = 高置信节点。

### 7.2 诊断表：召回率 × 可用率

per-skill 增量计数：被召回数 R(s)、好评 G(s)、差评 B(s)，O(1) 更新。

| | 可用率高 | 可用率低 |
| --- | --- | --- |
| **被召回多** | 健康，不动 | **内容病**：description 吸错查询/skill 本身没用 → 改 skill；**挪节点治不了内容病** |
| **被召回少** | **埋没**：路由够不着 → 向量离质心远 → 移节点/独立成簇 | 边缘 skill：观察，样本够再判 |

**关键归类规则：可用率低触发内容修订标记（人工队列），绝不触发节点移动**——这是最容易犯的归类错误。

### 7.3 "该去别的类"的判据：查询质心 vs 节点质心

对 skill s，取其**历史被召回时的 query 向量均值**（查询质心），与所在节点质心比 cosine：

- 查询质心离别的节点更近 → 移过去 / 软分配双挂；
- 查询质心孤悬 → 独立成簇（单成员节点，B+1，成本可忽略）。

依据 description 向量判断不如依据**实际被使用时的语义位置**科学——description 是作者声称的用途，查询质心是真实使用位置。

### 7.4 签名收割（从 embedding 过程收集潜在签名）

1. **记录**：每次 embedding 检索记 `(输入文本, 命中 skill, 分数)`；
2. **抽取**：对映射到同一 skill 的输入做**对比性 n-gram 分析**——找"在 ≥k 条指向该 skill 的输入中出现、在其他 skill 输入中几乎不出现"的 n-gram（n=3~8 词）；外加正则抽数值型签名（`LNK\d{4}`、`error code \d+`、引号内报错原文）；
3. **人审入库**：候选进审核队列 → 确认后写 frontmatter → 下次构建自动机生效。

### 7.5 双通道并发对比与按 skill 晋级

签名与 embedding 每次并发执行（自动机微秒级，embedding 反正要跑，边际成本≈一行日志）：

- 统计一致率：签名结论 vs embedding 结论的吻合度；
- **按 skill 晋级（不做全局开关）**：某 skill 的签名流与 embedding 一致率持续 ≥ 阈值（如 95%）→ 该 skill 单独翻为签名主通道、embedding 降为验证；不一致率回升 → 回滚；
- 系统任意时刻是"部分签名 + 部分语义"混合体；全局替代会在改写型输入上静默漏召回，故禁止。

### 7.6 统计卫生（三个偏差及缓解）

| 偏差 | 后果 | 缓解 |
| --- | --- | --- |
| 选择偏差：只有被召回的 skill 有评分 | 埋没的好 skill 永远不可见 | **ε 探索**：小概率把束宽 m 扩到 m+1（多臂老虎机标准做法） |
| 小样本噪声 | 召回 2 差评 1 ≠ 可用率 50% | **Wilson 得分下界**（Reddit 排序同款），样本不足自动保守 |
| 混淆偏差：评的是任务结果，非 hint 效用 | 高估 skill 贡献 | 评分绑定 `(query, skill, rank)` 三元组按 rank 分层；用**相对比较**（vs 节点均值）替代绝对阈值 |

维护防抖动：判定门槛 G(s)+B(s) ≥ 20；每个维护窗口限移动数量（滞回）。

## 8. 增删改与维护协议

| 操作 | 序列 | 成本 |
| --- | --- | --- |
| 增 | 写 SKILL.md → embed 一次 → 归入最近质心节点（或"未分类"桶）→ 质心增量更新 → 签名插自动机 | O(1) + 1 次 API |
| 改 | description 变 → 重嵌该条 → 质心修正（减旧加新）→ 触发器更新 | O(1) + 1 次 API |
| 删 | 打墓碑 → 惰性压实；自动机定期/按批重建 | O(1) |
| 重聚类 | 触发式局部再分配（不全局重排） | 摊销低 |

日志 schema（从第一天固定，预留评分位）：`(event_id, query, hits[{skill, score, rank, node_id}], ts, rating?)`。

## 10. 论文叙事要点

1. **自适应系统叙事**：扁平暴力 → 签名叠加 → 规模触发分层，每步有量化依据（免费区间实测、命中率曲线、帕累托标定），无一次性重写；
2. **"语料规范即索引"**：检索复杂度问题的解法不是更强的索引，而是更好的元数据约定——把索引工程问题转化为数据质量工程问题，后者随使用增值；
3. **独立推导与文献锚点重合**：两级质心路由 = cluster pruning/IVF；双通道 = shadow mode；隐式评分 = implicit feedback（Joachims 一脉）；Wilson 下界、ε-greedy、ARI、silhouette 均有标准出处；
4. **可测指标体系**：签名命中率（随时间增长曲线）、路由命中率 vs 搜索成本帕累托、按 skill 晋级比例、节点漂移频率。

## 11. 术语速查

| 术语 | 含义 |
| --- | --- |
| frontmatter | Markdown 文件头部 `---` 围栏内的机器可读元数据区（键值对） |
| trigger（触发签名） | skill 声明的字面"唤醒词"，出现在输入中即路由该 skill |
| 构建自动机 | 把所有签名插入共享前缀的 trie + 计算失配指针（KMP 同款），一次构建、单遍扫描全命中 |
| 影子日志 | embedding 检索的旁路记录（不改变行为），供标定与签名挖掘 |
| 质心 | 节点成员向量的均值（归一化后），路由用 |
| 软分配 | 一个 skill 同时属于 ≤2 个节点，解决边界归属 |
| 晋级 | 单个 skill 的签名通道经一致率验证后升为主通道 |
