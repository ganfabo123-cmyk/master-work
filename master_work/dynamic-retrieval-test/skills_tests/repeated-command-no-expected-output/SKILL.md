# 同一命令重复运行却只有 banner 输出：停止重试，对齐已知可用调用

## 适用场景

- 同一条 build/test/脚本命令在本 session 已运行 ≥2 次，输出几乎逐字相同；
- 退出码 0（或脚本吞掉了退出码），但没有出现预期的编译产物、进度行、测试结果；
- 输出只有工具横幅（banner）、版本信息、usage 帮助。

这通常意味着命令**根本没进入预期的工作分支**：参数解析失败静默打印帮助、cwd 不对导致脚本早退、或环境变量缺失走了默认分支。

## 处理步骤

1. 数一数：同一命令原样运行了几次？输出是否含预期标记（如 `.obj`/`.exe` 编译行、`PASS`、进度百分比）？两次都没有预期标记 → 触发本 skill。
2. 在本 session 历史里找**最近一次确实工作过的调用**（曾产出过预期输出的那一条），逐项对比：工作目录 cwd、完整参数（含引号和转义）、shell 类型（cmd vs PowerShell vs bash）、环境变量。
3. 检查产物时间戳：`ls build/` 或 `Get-ChildItem build/`，确认"成功"是否只是没有变化的旧产物。
4. 把命令缩短到最小可验证形态单跑一次（例如只编译一个文件），确认输出通路正常后再恢复完整命令。
5. 若脚本是 bat/cmd，确认用 cmd 而非 PowerShell 执行（PowerShell 对批处理参数与退出码的语义不同）。

## 不要做

- 不要第 3 次原样重跑同一条命令；
- 不要把"退出码 0 且有 banner"当作构建成功——成功与否看产物与预期输出标记；
- 不要在没有对照的情况下继续加参数试探。

## 证据来源

来自真实 session 审计：a20a4070（DMLS）——同一条 build 调用连续 4 次返回几乎相同的 banner 输出，而 session 早段存在一条确实工作过的调用；该案例是"同命令空转循环"检测的原型。
