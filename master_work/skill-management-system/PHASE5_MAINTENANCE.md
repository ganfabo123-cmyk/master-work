# 第五阶段：正式维护闭环

## 执行主线

```text
观测/评分事实 → 统计与查询质心 → 维护计划 → 过期与窗口校验
    → 副本中执行整批动作 → 全量不变量校验 → CURRENT原子发布
```

代码：maintenance.py扩展正式计划与执行；nodes.py增加独立节点；manager.py接入管理命令；
storage.py将维护队列和窗口日志纳入同代快照。范围固定为现有35个skill。
不替原检索程序接线，不创建后台维护任务，不调用远程API。

## 默认策略（暂定配置，不是效果标定结论）

| 配置 | 默认值 | 作用 |
| --- | ---: | --- |
| min_feedback_samples | 20 | 每个反馈分组至少20条评分才判断 |
| good_wilson_lower | 0.65 | 几何迁移要求的Wilson下界 |
| low_usability | 0.5 | 低于该可用率进入内容修订队列 |
| relative_margin | 0.1 | 同历史节点、同rank的足量同伴比较中落后超过该差值，也进入内容队列 |
| move_margin | 0.03 | 新节点比当前归属更接近查询质心的最小差值 |
| dual_min_similarity | 0.55 | 双挂第二节点的最低余弦相似度 |
| dual_max_gap | 0.04 | 最接近两个节点的最大相似度差 |
| orphan_similarity | 0.45 | 查询质心远离所有节点时考虑独立成簇 |
| max_moves_per_window | 3 | 移动、双挂、独立成簇合计上限 |
| max_splits_per_window | 1 | 局部拆分上限 |
| cooldown_windows | 2 | 成员变化后至少隔2个已执行窗口再调整 |
| min_new_feedback | 5 | 冷却结束后仍需至少5条未使用的新评分 |
| min_window_seconds | 3600 | 相邻窗口至少间隔1小时 |
| route_window_queries | 20 | 质量比较的前/后两个窗口各20条不同查询 |
| route_drop | 0.1 | 路由覆盖下降至少10个百分点 |
| route_recall_target | 0.95 | 近期覆盖低于该值才考虑质量触发拆分 |

真实、模拟、常规、探索反馈保留分组；正式计划忽略synthetic/fixture。
同一skill的不同分组若指向不同目的地则暂缓；可信低效用分组优先进入内容队列，不通过换节点掩盖内容问题。
同伴样本不足时明确缺少相对证据，仍按已有评分下界和查询几何判断，不伪造同伴基线。

## 归属动作

- move：迁到更合适的现有节点，或从双挂收敛到一个节点。
- attach：查询位置位于两个高相似节点的边界，最多双挂。
- isolate：查询位置远离全部节点时建立单成员节点；已独立项不会重复建同类节点。
- content_review：低可用率或相对效用落后，进入人工内容修订队列；不改变节点。

查询质心来自实际召回时的单位查询向量均值，节点质心始终来自当前成员的单位description向量。
独立成簇也不能把查询向量偷换为节点质心；description偏离用途时仍需人工修订，独立节点不保证检索效果提升。

## 局部重聚类

两类触发：

1. 节点成员数严格大于2×target_size。
2. 当前语料、当前布局、同k/tau/m的常规evaluation观测中，前后各20条查询的覆盖显著下降。

质量触发不混用旧布局或不同参数，不使用全局兜底的consumption结果冒充路由质量证据。
只替换受影响节点，保留其他节点及成员的其他归属；使用该布局的固定聚类种子和迭代参数。
子节点及受影响成员进入冷却期。不可分的节点记录暂缓原因，不伪造拆分。

## 计划、事务与审计

maintenance-plan保存完整actions、evidence、deferred。计划ID绑定输入指纹、模拟标记和动作摘要。
输入指纹包含语料状态、向量、布局、反馈、维护状态以及相关审核状态。
新增观测/评分、手工改归属、更新签名或维护配置后，旧计划会过期。

maintenance-apply会检查计划是否仍适用、执行时间是否到达窗口、移动与拆分数量是否超限。
所有动作先在深副本执行，任一动作或发布失败都不改变正式CURRENT。
已执行计划重试返回同一结果，不重复动作或递增窗口。
没有可执行动作的窗口仍记录检查结果，但不改变skill或节点。

同代新增文件：

```text
maintenance_queue.json  # 计划、内容修订项、人工关闭记录
maintenance_log.jsonl   # 各窗口完整动作、当时配置、前后布局指纹
```

state.maintenance保存窗口序号、时间、配置和成员/子节点冷却状态。
读取时校验计划摘要、窗口序号、结果计数、历史限额和评分引用；继续校验节点质心、签名索引及事实回放。

## 内容修订人工处理

```powershell
python -B manager.py maintenance-review --case <case_id> --decision resolved --reviewer <name> --reason <reason>
python -B manager.py maintenance-review --case <case_id> --decision dismissed --reviewer <name> --reason <reason>
```

同一skill/description版本共用一项，不重复入队。足量新反馈仍显示问题时可以重新打开，保留旧关闭记录。
resolved是审核者的处理声明，本命令不会自动改正文，也不声称已经验证修复效果。
