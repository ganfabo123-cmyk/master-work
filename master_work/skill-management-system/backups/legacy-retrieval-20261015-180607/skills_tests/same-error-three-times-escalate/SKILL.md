# 同一错误第三次出现：升级假设层次，禁止第四次同类重试

## 适用场景

- 同一份报错（错误类型 + 关键信息相同）在不同修复尝试后第三次出现；
- 每次修改后错误一字不差地复现。

两次失败可能是运气，第三次相同失败是统计证据：**当前假设层次错了**。继续在代码同层小修小改的期望收益趋近于零。

## 处理步骤

1. 列出已试过的修法清单（改了什么、为什么当时认为有效），确认三次错误签名确实相同（不是相似）。
2. 升级一层做最小复现：用 10 行以内的脚本/最小输入复现错误，剥离业务代码。
3. 核对环境性前提：依赖版本、解释器/编译器版本、文件路径存在性、权限、编码、平台差异（Windows 路径/换行/编码是高发区）。
4. 回到错误源头：读完整堆栈和错误对象，找出错误最早抛出的那一行，而不是最靠近输出的那一行。
5. 若最小复现仍无法定位或需要项目外部知识（密钥、账号、历史决策），直接向用户说明已试过的清单并提问。

## 不要做

- 不要进行第四次同类修改；
- 不要把"换个写法再试一次"当成新假设——先能解释前三次为什么失败；
- 不要在没有清单的情况下声称"试过所有方法"。

## 证据来源

来自真实 session 审计：860618e1——同一个 PDF 处理错误连续出现 3 次，agent 三次采用同层修法均告失败；该案例是"错误签名 ×3"触发器的原型。
