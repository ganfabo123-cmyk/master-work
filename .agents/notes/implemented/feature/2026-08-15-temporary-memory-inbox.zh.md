# Agent Note: Temporary memory inbox

Status: implemented

[English](2026-08-15-temporary-memory-inbox.md) | 中文

## Problem

新经验在记录时不一定能立即归入正式记忆树。要求模型在记录过程中检查并选择树路径，会把收集与整理混为一体，也可能把经验放在不合适的标题下。

## Decision

`memory_record` 默认把未分类经验收集到 `$DSH_HOME/temp_memory.md`，绝不改变正式的 `$DSH_HOME/memory.md` 树。记录无需先调用 `memory_children`，也不接收树路径。

每个条目包含标题、格式为 `YYYY-MM-DD HH:mm` 的 `recordedAt`，以及唯一的完整正文。正文遵循既有经验模板，包含事件日期、可确认时的事件时刻、结果依据、具体做法，以及因果分析与可迁移原则。`recordedAt` 标识记录创建时间，不会虚构事件时刻。

工具通过 `userQuestions` 请用户确认或编辑每条完整正文，空答案表示放弃。获准记录取得 `temp-memory-N` id，并与创建时间一起原子存储。正式 `memory-N` id 保持独立。

分类、合并、插入正式树和从临时收件箱移除记录属于后续管理工具。服务为受信调用方保留正式树插入能力，但 `memory_record` 只收集临时记录。

## Alternatives considered

- **让 `memory_record` 读取树后选择正式路径** — 拒绝，因为记录时不一定有足够上下文选择持久分类，而写前先读会耦合两个独立任务。
- **继续把行为、结果和反思作为独立工具字段** — 拒绝，因为这些片段重复了用户可见模板并限制编辑；唯一的完整正文才是经确认的记录。
- **两个文件复用 `memory-N` id** — 拒绝，因为独立分配的 id 会在后续管理工具把临时记录插入正式树时发生冲突。

## Consequences

- 记录与正式树导航相互独立，不会意外创建正式分支。
- 临时文件成为明确的待整理队列，带有记录时间元数据和独立 id 命名空间。
- 当前没有面向模型的操作列出、分类、插入、合并或移除临时记录；在管理工具定义完整生命周期之前，这些能力不可用。
- 本次行为变更具备源代码类型检查与文档验证，但按当前任务明确限制，没有更新单元测试覆盖。
